# Mini Auth PC 安全中心页面设计

## 背景与目标

mini-auth 当前 Web 前端只有登录页面。本次新增一个面向 PC 浏览器的账号安全中心，以飞书账号安全中心截图为视觉和排版参考，先使用前端模拟数据完成页面与交互，不连接后端接口。

本次目标：

- 提供与参考页面高度一致的页面层级、双栏排版、卡片样式、颜色和间距。
- 使用 mini-auth 自有品牌元素，不复制飞书 Logo、头像或客服机器人。
- 为主要入口提供可演示的本地交互。
- 保持现有登录页面与 `@mini-auth/auth-ui` 不变。

## 范围

### 包含

- 在 `frontend/apps/web/src` 内新增安全中心页面及其样式和页面内组件。
- `/accounts/security/` 展示安全中心。
- `/accounts/` 自动跳转到 `/accounts/security/`。
- `/` 继续展示现有登录页面。
- 使用 React 本地状态和静态模拟数据。
- 实现安全评分、登录设备、账号保护、账号管理、安全管理和安全指引区域。
- 实现开关、设备退出、详情查看及设置项弹窗等演示交互。
- 针对常见 PC 宽度完成布局；不专门设计移动端版本。

### 不包含

- 后端 API、数据库迁移或真实账号安全能力。
- 真实 MFA、密码修改、账号注销、设备会话撤销或应用授权操作。
- 修改 `frontend/packages/auth-ui`。
- 引入通用路由框架。
- 飞书品牌资产、原头像或客服机器人复刻。

## 页面路由

Web 应用根据 `window.location.pathname` 做轻量分流：

- `/accounts` 与 `/accounts/`：使用 `window.location.replace` 跳转至 `/accounts/security/`。
- `/accounts/security` 与 `/accounts/security/`：渲染安全中心页面。
- 其他路径：保持当前行为，渲染现有登录页面。

这样可以满足当前有限的页面数量，避免为单个新增页面引入额外路由依赖。

## 视觉设计

页面整体采用参考图中的 PC 账号中心结构：

- 顶部为固定视觉高度的白色导航栏，左侧显示 mini-auth 图形标识和“账号安全中心”，右侧显示帮助入口和模拟头像。
- 主背景使用非常浅的灰蓝色，并在首屏顶部加入克制的淡蓝渐变。
- 内容区居中，最大宽度约 1440px，主体为左右两列，列宽接近 1:1。
- 顶部问候区居中显示头像、用户名、欢迎语和说明文字。
- 内容卡片使用白色背景、约 12px 圆角、极浅边框或阴影以及充足留白。
- 标题和正文使用系统中文无衬线字体；主文字为深灰黑，说明文字为中性灰。
- 交互主色为明亮蓝色；未配置状态使用浅橙背景与橙色文字；危险操作使用红色。
- 图标使用项目内联 SVG 或 CSS 绘制，保持统一的线性图标风格，不新增大型图标依赖。

页面仅面向 PC。常见桌面宽度使用双栏布局；当窗口窄到无法容纳双栏时允许产生合理的最小宽度或横向滚动，不为移动端重新编排页面。

## 页面结构

### 顶部问候区

- mini-auth 模拟头像。
- 问候文案，例如“你好，Mini Auth 用户”。
- 说明文案，强调可在此管理账号安全设置。

### 左栏

1. **账号安全体检分**
   - 半圆形进度仪表。
   - 当前分数、安全等级和可优化项数量。
   - “前往优化”按钮滚动或聚焦到第一个未设置的账号保护项。

2. **登录设备**
   - 默认展示三台模拟设备。
   - 当前设备标记“本机”。
   - 其他设备提供“退出登录”按钮。
   - “操作记录”和“查看全部设备”打开详情弹窗。

3. **账号管理**
   - 账号申诉。
   - 账号注销，使用危险色强调。
   - 点击条目打开说明弹窗，不执行真实操作。

### 右栏

1. **账号保护**
   - 两步验证开关。
   - 登录方式、登录密码、通行密钥、动态口令、备用验证方式和安全密码。
   - 每项展示图标、名称、状态标签、说明和右箭头。

2. **安全管理**
   - 应用授权管理入口。
   - 点击后展示模拟授权应用列表弹窗。

3. **安全指引**
   - 帮助中心与在线客服两个并排入口。
   - 点击后展示本地演示提示，不跳转外部服务。

底部显示当前登录账号信息。

## 模拟数据与状态

页面在组件内定义有明确类型的模拟数据：

- 用户：昵称、邮箱、头像缩写。
- 设备：ID、浏览器或设备名、系统、登录时间、是否本机。
- 安全设置：ID、标题、说明、状态、图标类型和主题色。

交互状态包括：

- 两步验证是否开启。
- 当前设备列表。
- 当前打开的弹窗及其上下文。
- 操作成功后的轻量提示。

两步验证开启后，对应状态变为“已设置”，安全评分和可优化项数量同步变化；关闭时恢复。设备退出确认后，仅从本地设备数组中移除该设备，并展示成功提示。

## 组件边界

所有实现位于 `frontend/apps/web/src`，建议拆分为：

- `SecurityCenterPage.tsx`：页面状态、模拟数据与整体组合。
- `security-center.css`：页面专用样式。
- 页面文件内部的小型展示组件：卡片、设置行、图标、弹窗和提示。

`App.tsx` 只负责路径分流以及现有登录页和安全中心页的选择，避免把安全中心细节堆入应用入口。

本次页面规模有限，不额外建立通用组件库，也不修改 `@mini-auth/auth-ui`。

## 交互与异常处理

- 退出非本机设备前展示确认弹窗；取消不改变数据。
- 本机不展示退出按钮。
- 模拟设置项点击后显示对应标题、说明和“演示页面暂未连接后端”的提示。
- 所有弹窗支持关闭按钮、遮罩点击和 `Escape` 键关闭。
- 按钮和设置行具备 hover、active、focus-visible 状态。
- 动画使用轻量 CSS transition；尊重 `prefers-reduced-motion`。
- 本轮没有网络请求，因此无需设计加载失败或接口错误状态。

## 可访问性

- 使用语义化的 header、main、section、button 和 heading。
- 图标装饰标记为 `aria-hidden`；只有图标的按钮提供 `aria-label`。
- 弹窗使用 `role="dialog"`、`aria-modal="true"` 和可辨识标题。
- 开关使用原生 button 与 `role="switch"`、`aria-checked`。
- 文本与背景保持清晰对比度，键盘焦点可见。

## 验证方案

- 运行 TypeScript 和 Vite 生产构建，确保无类型及打包错误。
- 启动本地开发服务器并验证：
  - `/` 仍是现有登录页。
  - `/accounts/` 正确重定向。
  - `/accounts/security/` 正确渲染。
  - 两步验证会更新评分和状态。
  - 退出设备确认、设置弹窗、详情弹窗和提示均可用。
- 在 PC 浏览器中对照两张参考截图检查布局、字号、留白、卡片尺寸、颜色和首屏内容密度。
- 检查控制台无运行时错误，并用键盘验证主要交互。

## 完成标准

- 安全中心在指定路由可访问，现有登录页没有回归。
- 首屏结构、双栏卡片排版和视觉层级与参考图高度一致。
- 所有约定的模拟交互能够完成且状态反馈明确。
- 代码只落在 `frontend/apps/web/src` 与必要的入口改动中。
- 项目构建通过，PC 浏览器检查无明显布局或控制台问题。
